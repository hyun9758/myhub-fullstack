# career.period는 구조화된 시작/종료일이 아니라 자유 텍스트 한 줄로 저장한다

PRD 데이터 스키마(4장)는 `career[]`의 기간을 처음부터 단일 `period` 필드(자유 텍스트)로 정의하고 있었다. 그릴링에서 이를 education처럼 `start_date`/`end_date` 두 값으로 나누는 대안과 비교했다. 자유 텍스트는 "재직중", "2022년 여름" 같은 자연스러운 표현을 허용하지만 정렬 정확도가 떨어지고, 구조화된 날짜는 정렬은 정확해도 표현이 날짜 형식으로 제한된다. 소유자는 이력서에 실제로 자유로운 기간 표현(예: "2025.12 ~ 2026.02")을 쓰고 있고, 스키마가 이미 이렇게 고정되어 있다는 점(그릴링 규칙상 4장 스키마 자체는 변경 불가)을 근거로 원안(자유 텍스트)을 유지하기로 했다.

**대안**: education과 동일하게 `start_date`/`end_date` 구조화. 기각 이유 — PRD 데이터 스키마(4장)가 이미 `period` 단일 필드로 고정되어 있어 그릴링 범위에서 변경할 수 없는 전제였고, 자동 정렬(ADR-0001)의 실익도 학력만큼 크지 않다고 판단.

**참고**: 이 때문에 career 목록의 "최신순 자동 정렬"은 저장된 텍스트의 사전식 정렬에 의존하므로 education만큼 항상 정확하지는 않을 수 있다 (`specs/design/myhub_data_req.md` 8장 미결 사항 참고).
